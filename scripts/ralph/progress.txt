## Codebase Patterns
- CC Switch already has Codex proxy takeover, provider hot-switch UI synchronization, failover routing, session-id extraction, and local history migration; extend those paths instead of introducing a second proxy service.
- Codex provider changes may invalidate reasoning.encrypted_content. Portable handoff must preserve user-visible conversation data while treating provider-bound encrypted reasoning as non-portable.
- Responses API item `id` values are provider-scoped, while `call_id` and attachment `file_id` values carry portable tool/output and file linkage; sanitization must not conflate them.
- Keep request sanitizers scoped to the Responses `input` history so similarly named keys in request metadata or tool schemas are not accidentally rewritten.
- Keep Codex route ownership in `ProxyState` and represent each request as an uncommitted attempt; only a fully successful completion may commit its provider, while dropping headers-only or partial-stream attempts leaves ownership unchanged.
- Derive every failover candidate body from the original Responses request, then sanitize against the last fully successful provider; carry the route attempt with the response lifecycle and commit only on a complete body or `response.completed` SSE event.
- Never modify Codex session JSONL, state databases, history indexes, attachments, or provider secrets while reconstructing a transcript.
- Locate a Codex rollout by an exact UUID filename suffix, then verify the same UUID in `session_meta`; canonicalize the Codex home, session root, and file before any read, and never follow session-tree symlinks.
- Treat rollout `compacted`, reasoning, event, context, and world-state records as internal; portable visible transcripts come only from user/assistant `response_item` messages, attachment references, and completed tool outputs.
- Compare the rollout's trailing user message with the current Responses input after applying the same visible-content normalization; only remove an exact match, because the rollout write may lag the proxy request.
- Detect portable transcript requests before provider-specific format conversion, and suppress full request-body debug logging for the rest of that attempt; transformed Chat payloads may no longer retain the Responses marker shape.
- For backward-compatible default-on settings, pair Rust `#[serde(default = "default_true")]` with the same `true` default in `AppSettings::default` and every frontend form initialization/reset baseline; preserve explicit `false` with nullish fallback rather than truthiness checks.
- The standalone Vite renderer cannot populate settings without Tauri `invoke`; browser-check settings components with a temporary harness that mounts the real component, i18n resources, and project styles, then remove the harness before committing.

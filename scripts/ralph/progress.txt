## Codebase Patterns
- CC Switch already has Codex proxy takeover, provider hot-switch UI synchronization, failover routing, session-id extraction, and local history migration; extend those paths instead of introducing a second proxy service.
- Codex provider changes may invalidate reasoning.encrypted_content. Portable handoff must preserve user-visible conversation data while treating provider-bound encrypted reasoning as non-portable.
- Responses API item `id` values are provider-scoped, while `call_id` and attachment `file_id` values carry portable tool/output and file linkage; sanitization must not conflate them.
- Keep request sanitizers scoped to the Responses `input` history so similarly named keys in request metadata or tool schemas are not accidentally rewritten.
- Keep Codex route ownership in `ProxyState` and represent each request as an uncommitted attempt; only a fully successful completion may commit its provider, while dropping headers-only or partial-stream attempts leaves ownership unchanged.
- Derive every failover candidate body from the original Responses request, then sanitize against the last fully successful provider; carry the route attempt with the response lifecycle and commit only on a complete body or `response.completed` SSE event.
- Never modify Codex session JSONL, state databases, history indexes, attachments, or provider secrets while reconstructing a transcript.
